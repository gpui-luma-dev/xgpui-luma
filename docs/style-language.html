Luma/Looks/Style language

Style language (.lss)

Every color, size, font and state a control paints comes from a .lss file: one file per control in the SDK, and one per control in each Look that restyles it.

Why a style language

Before .lss, a control’s appearance was spread across Rust: an SDK theme built from tokens, a palette per look, rule tables, size presets, adapters and inspector code that re-derived the same values to show them. Changing one hover color meant finding the right one of several places, and the inspector could drift from what was painted.

The style language puts the appearance in one place per layer:

  • One file to read. The SDK’s button.lss says what a button looks like by default; Shadcn’s button.lss says only how Shadcn differs. There is no other place a button color comes from.
  • The file is the schema. A control’s properties are declared in its SDK file with a kind (length, color, …) and a doc comment, so files are checked when they load and tools can list every property without per-control Rust.
  • Every value knows where it came from. Resolution records the rule that won, the rules it beat and the tokens it read. The Studio and lab inspectors show exactly that, so what you inspect is what is painted.
  • Less code. The migration replaced about 14,000 lines of look-specific Rust with about 2,400 lines of .lss.

Behavior stays in Rust: controls own state, input, focus and events; templates own structure. .lss only answers “what does this part look like in this state, at this size, in this variant?”.

Layers: the SDK, then a Look

Style files are loaded in layers. The SDK layer declares each control and gives it working defaults, so SDK controls render on their own. A Look layer (Shadcn, Radix, or your own) is compiled over it and changes only what it needs. An app layer can sit on top the same way.

LayerWhereWhat it does
SDKcrates/sdk/src/controls/**/<control>.lss, crates/sdk/src/theme/{tokens,palette,palette-dark}.lssDeclares controls, parts and properties; sets defaults from SDK tokens.
Shadcncrates/look-shadcn/src/style/*.lssRestyles controls with the theme’s CSS variables (css.*).
Radixcrates/look-radix/src/style/*.lssRestyles controls with Radix color scales (gray[n], accent[n], tone[n]).

A later layer wins over an earlier one property by property, so a Look that sets only background keeps the SDK’s sizes, fonts and focus ring.

Anatomy of a file

This is the start of the SDK button (crates/sdk/src/controls/button/button.lss):

.lss · SDK button
/// A pressable face with a label or an icon.
button {
  /// Whole-control opacity when disabled.
  disabled_opacity: number = metrics.disabled_opacity
  height    = metrics.control.control_height
  padding_x = metrics.control.padding_x
  radius    = exact(metrics.control.radius)
  /// Icon size for icon buttons, and for icons beside a label.
  icon_size: length = metrics.control.icon_size

  /// The face.
  part root {
    background   = palette.surface.subtle.background
    foreground   = palette.app.foreground
    border       = palette.border.default
    focus_border = palette.focus.ring
    font_size    = typography.text.label.size
    transition   = motion.default
    :hover    { background = palette.state.hover.background }
    :pressed  { background = palette.state.pressed.background }
    :disabled { background = palette.state.disabled.background  foreground = palette.state.disabled.foreground }
  }
}
ConstructMeaning
button { … }A control. Its own properties belong to its root part.
name: kind = exprA declaration: a new property with a kind and, with ///, a doc comment. Only the SDK layer declares.
name = exprAn assignment to a core property (background, radius, font_size, …) or a declared one. Unknown names are errors.
part p { … }A paintable piece of the control: a table has root (the frame), header and row; a slider has track, fill and thumb.
:hover { … }, :selected:pressed { … }A state block: applies when all listed states hold.
variant ghost { … }, size sm { … }A scope: applies only when the instance has that attribute value. Scopes nest.
toggle extends buttonStart from another control: every layer’s button rules also style toggle, so a Look’s button restyle reaches its toggles.
name := exprAn owning assignment: less specific rules for that property (including the base state rules) stop applying, so a variant can replace a property without restating every state.

How a Look restyles a control

A Look file names the same control and sets only what differs. Shadcn’s button paints the face from the theme’s CSS variables and adds its variants, sizes and corner presets:

.lss · Shadcn button (excerpt)
button {
  padding_x = 16
  size sm { padding_x = 12 }
  size lg { padding_x = 20 }
  radius none  { radius = exact(0)                    icon_radius = exact(0) }
  radius small { radius = exact(shadcn.radius_small)  icon_radius = exact(shadcn.radius_small) }
  radius full  { radius = exact(height / 2)           icon_radius = exact(height / 2) }

  part root {
    background := css.primary
    foreground := css.primary_foreground
    :hover    { background = css.primary_hover }
    :pressed  { background = css.primary_pressed }
    :disabled { background = css.muted  foreground = css.muted_foreground }
  }

  variant ghost {
    part root {
      background := transparent
      foreground := css.foreground
      border     := none
      :hover    { background = shadcn.ghost_active  foreground = css.accent_foreground }
      :disabled { background = transparent  foreground = css.muted_foreground }
    }
  }
}

Radix does the same with its color scales and adds a tone and a contrast state; a badge, for example:

.lss · Radix badge (excerpt)
badge {
  part root {
    background = tone[3]
    foreground = tone[11]
    :high_contrast { foreground = tone[12] }
  }
  size 1 { part root { radius = exact(3)  padding_x = exact(6)  padding_y = exact(2) } }

  variant solid {
    part root {
      background = tone[9]
      foreground = look.tone_contrast
      :high_contrast { background = tone[12]  foreground = tone[1] }
    }
  }
}

Attributes and states are configured per Look. The SDK declares variant and size and the interaction states (hover, pressed, focused, disabled, plus control states such as selected and checked). Shadcn adds a radius attribute (none|small|medium|large|full); Radix adds tone and radius attributes and a high_contrast state. A Look’s base values are its default size: Shadcn writes size sm and size lg over md, Radix writes size 1 and size 3 over 2.

How a value is chosen

To paint a part, the control asks for one key: the control, its attribute values (variant, size, …) and its active states. For each property every rule whose scope and states match the key is a candidate, and the highest-ranked one wins:

  1. More states wins (:selected:hover beats :hover).
  2. An interaction state beats a non-interaction state at the same count (:hover beats :selected).
  3. More attributes wins (a variant ghost rule beats the base rule for the same states).
  4. A higher layer wins (Look over SDK).
  5. The control’s own rule beats one reached through extends.
  6. Later in the file wins.

The interaction states are exclusive, disabled > pressed > hover: only the strongest one active stays in the key, so a disabled control never takes hover or pressed rules. An owning assignment (:=) removes less specific candidates before ranking.

Tokens, functions and lengths

  • Tokens are named values shared by every control: the SDK’s metrics, palette, typography, elevation and motion (in theme/tokens.lss and the light and dark palette files), and a Look’s own groups (shadcn.*, radix.*). Tokens can be scoped by size and by mode light / mode dark; control files never branch on mode.
  • Native roots come from Rust rather than files: Shadcn’s css.* reads the theme’s CSS variables (css.primary_hover derives hover and pressed layers the CSS doesn’t list); Radix’s gray[n], accent[n] and tone[n] read the Look’s scales.
  • Functions: built-ins such as alpha, mix, first (the first value that exists, for themes missing a variable), min, max, exact, box_shadow and inset_shadow, plus Look functions (Shadcn action_layer, darken; Radix shift_lightness).
  • No units. A property’s kind says what a number means. Lengths snap to whole pixels unless written exact(…); text sizes are never snapped.

How Rust reads the files

A control binds to its style with a StyleBinding: the control name, a theme source and any fixed attributes. A Styled* reader resolves the binding for the current states and turns the values into the structs the control’s template draws:

Rust · Binding a Look’s tabs
use std::sync::Arc;
use xgpui_luma::controls::tabs::StyledTabs;
use xgpui_luma::style::{StyleBinding, ThemeSource};

// `look` is a ShadcnLook. A live source re-reads the Look's theme on each render,
// so mode or theme changes repaint without rebuilding the control.
let source = look.clone();
let binding = StyleBinding::new("tabs", ThemeSource::Live(Arc::new(move || source.style_theme())))
    .attr("size", "sm");
let tabs = StyledTabs::new(binding);
let item = tabs.item(true, Default::default()); // the active tab at rest

Illustrative: Looks build these bindings for you; you write one only to style a control yourself.

The SDK’s default_*_theme() functions return readers over the SDK files alone, so SDK controls render without a Look. Button-family controls draw with StyledButtonTemplate, which picks button or toggle by the render model’s role. A few things stay in Rust beside the files, where a value depends on the instance rather than the style (for example a Radix avatar’s full radius is half its diameter).

Inspecting and editing

Resolution can explain itself. Theme::inspect returns, for every part and property, the value, the rule that won, the rules it beat and the tokens it read. Luma Studio’s control inspectors and the lab Workshop’s style column are built on this alone, so they need no per-control code and always match what is painted.

Files can also be changed at runtime: Stylesheet::apply takes edits (replace a rule’s expression, or insert a rule) and returns the recompiled stylesheet or diagnostics, and Overrides set a value on one control instance. Edits export back to .lss text.

Finding a control’s style

Each SDK control’s file sits beside its code: crates/sdk/src/controls/button/button.lss, …/navigation/tabs/tabs.lss, …/collection/table/table.lss. Each Look has one file per control it restyles under src/style/, named after the control, and lists them in src/style/mod.rs. Every file starts with a comment saying which layer it is and what reads it.
